## 1. The change in one paragraph

`SessionEngine.run_session` runs a whole session in one in-process call, holding the per-capability
decision-memory accumulator (`_CapMemory`) in a process-local `dict`. The device-driven runtime instead
receives **one set per request**, each its own transaction with no shared memory — so the accumulator must
be **persisted** (review §5.2). DX-11 adds (a) an additive infra table **`session_progress`** (migration
008, Schema v8) holding, per `(session, capability)`, the `_CapMemory` fields, and (b) a **`SessionRuntime`**
engine exposing `start_session` (≡ `SessionEngine` steps 1–2, **reused** via an extracted
`compose_and_open`), `report_set` (≡ step 3 for one set: `report_set_fatigue_aware(govern=False)` then
upsert the accumulator), and `complete_session` (≡ steps 4–5: `complete_block` once per capability in
`CAPABILITY_PRIORITY_ORDER`, then close + increment). The athlete's logged `(actual_weight, actual_reps)`
is carried via the same `perform` callback the pipeline already takes (M1). **The differential-replay gate
(review §7) is the acceptance test:** an event-driven replay must reproduce `SessionEngine`'s
`capability_state` (score / confidence / sum_w / fatigue / decision memory) **bit-for-bit**.

## 3. `session_progress` — the persisted accumulator (migration 008, Schema v8)

Additive **infra** table (outside the model zones; no model number/column meaning changes), mirroring
`SessionEngine._CapMemory` one-to-one:

```sql
CREATE TABLE IF NOT EXISTS session_progress (
    workout_session_id  TEXT NOT NULL REFERENCES workout_session(id),
    capability          TEXT NOT NULL,
    entry_score         REAL,                         -- score before the cap's FIRST set this session
    s_obs               REAL NOT NULL DEFAULT 0,      -- representative observed score (primary slot preferred)
    decision_type       TEXT NOT NULL DEFAULT '',
    recommended_weight  REAL NOT NULL DEFAULT 0,
    have_primary        INTEGER NOT NULL DEFAULT 0,   -- 0/1
    updated_at          TEXT NOT NULL,
    PRIMARY KEY (workout_session_id, capability)
);
```

  if absent (`migration_007` shape: idempotent, self-guarded by `already_applied`), stamps version 8.

- **runner** registers `migration_008_session_progress` in `MIGRATIONS` → `SCHEMA_VERSION == 8`; the fresh-DB

## 5. `SessionRuntime` — the event-driven primitive (`hush_model/persistence/runtime.py`)

Owns the request `Database`, a `LearningPipeline`, a `SessionEngine` (for `compose_and_open`), and a
`SessionProgressRepository`. Writes **no** model logic (mirrors `SessionEngine`).

```python
class SessionRuntime:
    def start_session(self, athlete_id, week, session_index, seed, target_reps=8):
        # ≡ SessionEngine steps 1–2 (load-free compose, persist blocks). Returns (session_id, plan, block_ids).
        return SessionEngine(self.db).compose_and_open(athlete_id, week, session_index, seed, target_reps)

    def report_set(self, athlete_id, session_id, block_id, capability, exercise, difficulty_factor,
                   target_reps, set_number, perform, week, is_primary_slot):
        # ≡ step 3 for ONE set. govern=False, week pinned by caller from the session row (review §5.3).
        res = self.pipeline.report_set_fatigue_aware(
            athlete_id, session_id, block_id, capability, exercise, difficulty_factor,
            target_reps, set_number, perform, week, govern=False)
        # update the PERSISTED accumulator exactly as SessionEngine updates _CapMemory (session.py:101–109):
        with self.db.transaction() as conn:
            repo = SessionProgressRepository(conn)
            acc = repo.get(session_id, capability)               # defaults if absent
            if acc.entry_score is None:
                acc.entry_score = res.score_before               # session-entry score for this capability
            if is_primary_slot or not acc.have_primary:
                if set_number == 1:
                    acc.decision_type = res.decision_type
                    acc.recommended_weight = res.recommended_weight
                acc.s_obs = res.s_obs
            if is_primary_slot:
                acc.have_primary = True
            repo.upsert(session_id, capability, acc)
        return res

    def complete_session(self, athlete_id, session_id, week):
        # ≡ steps 4–5. complete_block ONCE per capability in CAPABILITY_PRIORITY_ORDER (review §5.1, R2).
        with self.db.transaction() as conn:
            accs = SessionProgressRepository(conn).all_for_session(session_id)   # {capability: acc}
        for capability in sorted(accs, key=_cap_rank):
            acc = accs[capability]
            self.pipeline.complete_block(
                athlete_id, capability, week,
                score_at_block_entry=acc.entry_score if acc.entry_score is not None else 0.0,
                block_s_obs=acc.s_obs, decision_type=acc.decision_type,
                recommended_weight=acc.recommended_weight)
        with self.db.transaction() as conn:
            sess = SessionRepository(conn)
            for b in sess.blocks_for_session(session_id):
                if b["status"] not in ("completed", "skipped"):
                    sess.set_block_status(b["id"], "completed")
            sess.complete_session(session_id)
            StateRepository(conn).increment_workout_count(athlete_id)
```

- **`perform`** carries the M1 input pair. The production endpoint passes
  `perform=lambda rec: (reported_actual_weight, reported_actual_reps)` (DX-01/DX-11 — the logged load
  reaches the chain); the differential test passes the synthetic athlete's `perform` to **both** paths.
- **`week`/`govern` pinned** (review §5.3): `week` from the session row; `govern=False` always (a single-set
  `govern=True` would advance the governor per set — forbidden).
- **`complete_block` deferred to close, once per cap, priority order** (review §5.1 — the recommended variant,
  not the riskier per-block-last-set variant in Build-Plan §7).
- **`is_primary_slot`** is supplied by the caller (the endpoint has the frozen composed plan, exactly as
  `SessionEngine` reads `bp.is_primary_slot`); DX-11 keeps it a parameter rather than persisting a new
  model column.

`SessionProgressRepository(conn)`: `get(session_id, capability) -> _Acc` (defaults: `entry_score=None,
s_obs=0.0, decision_type="", recommended_weight=0.0, have_primary=False`), `upsert(session_id, capability,
acc)` (INSERT OR REPLACE), `all_for_session(session_id) -> dict[str,_Acc]`.

## 6. Tests (`implementation/sprint5/test_sprint5.py`) + Wave-1 re-gold

- **`test_event_driven_matches_session_engine_bit_for_bit`** — **the acceptance gate (review §7).** Steady
  state (confidence 80, sum_w 40 ⇒ 2 slots/cap, exercising the multi-slot R2 accumulator), deterministic
  synthetic athlete (`rep_noise_sd=0`). Run a session via `SessionEngine.run_session`; run the *same*
  session (same seed/week, same `perform`) via `start_session` → per-set `report_set` (plan order) →
  `complete_session`. Assert every capability's `score / confidence / sum_w / fatigue / consecutive_positive
  / consecutive_negative / last_recommended_weight / last_decision` is **equal** across the two DBs.
- **`test_report_set_carries_actual_weight`** — DX-11 core: report a set with
  `perform=lambda rec: (rec.recommended_weight + 10.0, reps)`; assert the persisted observation's
  `actual_weight == recommended + 10` and the chain learned from it (s_obs reflects the heavier load) —
  `actual_weight` carried through the event-driven chain.
- **`test_accumulator_persists_across_requests_R2`** — report each set as a separate `report_set` call (own
  txn), then `complete_session`; assert decision memory advanced **once per capability** (`consecutive_*
  ≤ 1` for a single session) — i.e., the persisted accumulator survived across the independent requests.
- **`test_migration_008_additive_and_idempotent`** (in `test_wave1.py`) — apply on a v7-like DB: table
  created, version 8 stamped, second apply a no-op.
- **Wave-1 re-gold (stated):** `test_runner_chain_is_ordered_and_single_source`,
  `test_runner_applies_in_order_and_is_idempotent`, `test_fresh_db_reports_full_schema_version` updated from
  `[2..7]`/`7` to `[2..8]`/`8`.
