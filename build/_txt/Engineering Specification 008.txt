Purpose
Define the canonical meaning of every capability score.

Core Principle
Principle #49
Every capability must have a real-world anchor.

Capability Scores cannot be arbitrary numbers.
Every score must correspond to a measurable physical performance.

Cross-Capability Rule
Scores are comparable.

Example:
horizontal_push: 65horizontal_pull: 40

Interpretation:
Push capability significantly exceeds pull capability.

This enables:
Capability Imbalance Detection
which ES-006 uses for future strategy evaluation.

Confidence Initialization
Every seeded capability starts with:
confidence: 10

Regardless of score.

Reason:
We have a prior.
Not knowledge.

Calibration Philosophy
Important:
These tables are not truths.
They are priors.

The model is expected to move away from them as evidence accumulates.

Versioning
Capability calibration tables are versioned.

capability_model_version
must be stored on:
recommendationsobservationsstate_updates

Reason:
Future calibration changes must not rewrite history.

Success Criteria
The calibration matrix succeeds if:
Initial recommendations are reasonable. 
Capability scores have consistent meaning. 
Cross-capability comparisons are possible. 
Confidence grows independently of score. 
Future model versions remain auditable. 

Final Principle
Principle #50
A capability score is only useful if it means the same thing today, tomorrow, and six months from now.
