# Hush — Apple Watch Workout Experience Specification

**Status: CANONICAL — founder-approved 2026-06-15 (final UX adjustments applied).**
This is the source of truth for all future Apple Watch development. The watch
implementation (native target, WatchConnectivity, SwiftUI screens) must conform to
this document. Architecture and data-flow are defined in `NATIVE_SURFACES.md` §4
and in `src/platform/watch/*` + `src/platform/sessionMirror.ts`; this document
defines the **athlete experience**.

> The watch is a **coach, not a dashboard**. It tells you the one thing to do
> next, taps your wrist when it's time, and is otherwise silent. The phone does
> all the thinking; the watch renders and relays. It never shows a number it
> invented or a state it cannot back up.

## 1. Global design language

### 1.1 Typography hierarchy (one scale)

| Role | Use | Treatment |
|---|---|---|
| **Hero** (~52–60pt, tabular) | The single glance target: rest countdown, target load | SF Pro Rounded, semibold, monospaced figures |
| **Title** (~24pt) | State word, exercise name (where shown) | Medium, full white |
| **Body** (~17pt) | `Next:` block, next set | Regular, ~70% white |
| **Encouragement** (~17pt) | The coaching line | Regular, warm accent |
| **Caption** (~13pt) | Set label (`Set 3 of 4`), status | Regular, ~45% white |
| **Action label** (~15pt) | Names a button | Medium |

Exactly **one Hero per screen**. Hierarchy is carried by size and opacity, not
color.

### 1.2 Color

Pure black background (#000000). Text in three white opacities. **One warm
accent**, reserved for the coaching voice (encouragement, receipts) and the live
rest countdown — the accent is how you know Hush is speaking. No status
green/red/amber palette. Disabled controls ~30% white.

### 1.3 Interaction model

- **One tap per action.** Common actions are a single, large tap target — never a
  menu, never a precision target.
- **No navigation tree.** No tabs, no back, no scroll-to-find. The workout is the
  only navigation and it advances on its own.
- **Digital Crown is inert during training** (rest is Hush-owned and not
  adjustable) — the coach sets the pace. Its **one** purpose is the rep-adjustment
  screen (§2.6b), where it sets the actual reps performed.
- **No swipes, no force-press, no hidden gestures.** Every action is visible.
- **Pause** is a small persistent affordance (top corner) on Active Set, Inter-Set
  Rest, and Transition Rest. **Finish** is reachable only from Paused, behind an
  explicit confirmation (§2.7).

### 1.4 Deliberately absent

No heart rate, calories, rings, charts, exercise list, music, maps, or streaks.
**No session/exercise progress** (`Exercise 3 of 7`, `3 / 14`) — it is not
actionable and does not help the next rep. If it is not the next thing to do, it
is not on the watch.

### 1.5 Consistent set language

There is one set-language form across the entire experience: **`Set 3 of 4`**.
Never `3 / 4`, never `Exercise 3 of 7`. The only counter the athlete sees is which
set they are on within the current exercise.

### 1.6 No-scroll requirement (strict)

**Every screen must fit completely on a single watch screen with no scrolling**, on
the smallest supported watch. The Digital Crown does not scroll content (it is
inert). To keep within the budget:

- One **Hero**, a few support lines, and at most the actions a state needs.
- **Pause is a corner glyph, not a stacked row.** Secondary actions are compact,
  single-line text actions beneath the primary button.
- If a state ever cannot fit, **simplify content until it does** — never add a
  scroll. Concretely, Active Set keeps `Complete Set` + `Couldn't Complete`; the
  first-set-only `Exercise Busy` renders as a compact text action.

§7 confirms each approved screen against this requirement.

### 1.7 Authority handshake (experience level)

The phone owns the workout. A watch tap gives **instant local acknowledgment**
(haptic + subtle settle) so it never feels laggy, but the screen **advances only
when the phone confirms** the new state. Taps cannot double-count or land on the
wrong set; the phone validates every intent against its own truth and ignores
anything stale or duplicate. Anything the phone cannot confirm is shown as
*Reconnecting* (§2.8) — never as a false success.

## 2. States

### 2.1 Active Set

The coach hands you the prescription.

```
Bench Press

80kg × 8

Set 3 of 4

[ Complete Set ]
  Couldn't Complete
```

(On the first set of a newly started exercise, a compact `Exercise Busy` text
action also appears — see §2.6a.)

- **Visible information:** exercise name (Title, top — the only screen that states
  it, so rests never repeat it); target load × reps (**Hero**); set label (`Set 3
  of 4`). **No session/exercise progress.** A **receipt line** (warm accent)
  appears only when one is earned on this set, then is gone.
- **Typography:** Title = exercise → Hero = `load × reps` → Caption = set label.
  Receipt, when present, is the sole accent.
- **Actions (one tap each):**
  - **Complete Set** — primary, large. Accepts the recommended target verbatim.
    Editing weight/reps is **phone-only** by design; the watch keeps you moving,
    the phone keeps the record exact.
  - **Couldn't Complete** — secondary. Opens the rep-adjustment screen to report
    the actual reps performed (§2.6b).
  - **Exercise Busy** — compact, present **only on the first set of a newly
    started exercise** that has a later exercise (mirrors the phone exactly, §2.6a).
  - Pause affordance, top corner (a glyph, not a row).
- **Haptics:** silent on arrival. **Set Complete** on Complete Set (or **Receipt**
  if one is earned). Couldn't Complete is silent on open (it just opens §2.6b); the
  **Set Complete** tick fires when the adjusted reps are confirmed.
- **Transitions:** Complete Set → Inter-Set Rest (rest > 5s) · or directly to the
  next Active Set (rest ≤ 5s, skipped) · or, if it was the exercise's last set, →
  **Exercise Complete** (§2.4) · or, if it was the session's last set, → Workout
  Complete (§2.8). Cross-fade only. (Couldn't Complete advances the same way.)
- **Wrist-down / wrist-up:** no live timer, so the Always-On frame is static and
  dimmed (exercise name + target). A glance reads the prescription without waking
  the screen. Wrist-up brightens; actions live.
- **Failure states:** if the Complete Set tap cannot reach the phone, the watch
  does **not** advance and does **not** queue; it withholds the confirmation and
  enters *Reconnecting*. On reconnect the set logs once, never twice.

### 2.2 Inter-Set Rest (same exercise) — *replaces the previous rest design*

The coach holds you, then sends you. The athlete already knows the exercise, so
**the exercise name is not repeated.**

```
   01:30

Next:
80kg × 8

You can do this.

Set 3 of 4
```

- **Visible information — exactly four things, nothing else:**
  1. remaining rest time (**Hero**, tabular, warm accent),
  2. next prescribed set as load × reps (`Next:` block — **no exercise name**),
  3. encouragement (`You can do this.`),
  4. the current set (`Set 3 of 4`).
- **Typography:** Hero = countdown → Body = `Next:` load×reps → Encouragement
  (accent) → Caption = set label.
- **Actions:** whole screen = **Ready** (end rest now, one tap). Pause affordance.
- **Haptics:** **Rest Complete** the instant rest elapses — **fires wrist-down**,
  so you feel the go with your arm at your side. Ready (early) gives a Set-Complete
  Tick on send.
- **Transitions:** on elapse or Ready → next Active Set (same exercise),
  cross-fade countdown → target.
- **Wrist-down / wrist-up:** the **Always-On countdown stays live and accurate**
  (derived from an absolute end instant) — the signature gym moment. Wrist-up adds
  the `Next:` block, encouragement, and the Ready action.
- **Failure states:** on disconnect, the countdown keeps running (it is derived,
  therefore safe) with a quiet *Reconnecting* marker, and the Rest-Complete haptic
  still fires. **Ready is disabled** while disconnected (Hush never queues an
  advance). If still disconnected at elapse, the screen calmly reads *Continue on
  iPhone*.

### 2.3 (reserved)

*Transition Rest is §2.4-adjacent; numbering kept stable for cross-references.*

### 2.4 Exercise Complete (new transition state)

A short-lived state between exercises that reinforces progress and creates
momentum. It clearly separates one exercise from the next.

```
Bench Press Complete

Next:
Incline Press
```

- **Visible information:** `<Just-finished exercise> Complete` (**Title/Hero**);
  `Next:` + the upcoming exercise name. No load, no timer, no actions.
- **Typography:** Hero = `<Exercise> Complete` → Body = `Next:` exercise.
- **Actions:** none — it is automatic and brief (~1.5–2.0s). Not tappable past;
  it self-advances.
- **Haptics:** the dedicated **Exercise Complete** pattern (see §3) — its own
  signature, distinct from set and rest.
- **Transitions:** Active Set (last set of exercise) → **Exercise Complete** →
  **Transition Rest** (§2.5). Skipped when the completed set was the session's
  last (that moment belongs to Workout Complete).
- **Wrist-down / wrist-up:** if the wrist is down, the **Exercise Complete haptic
  still fires** so the boundary is felt; the visual is brief and not required.
- **Failure states:** purely presentational; if the next mirror has not arrived
  when the interstitial ends, it bridges into *Reconnecting* rather than a guess.

### 2.5 Transition Rest (between exercises) — distinct from Inter-Set Rest

Mentally prepares the athlete for a **new** exercise and builds anticipation. Here
the exercise name **is** shown (it is new), and the encouragement is forward-
leaning.

```
   01:30

Next:
Bench Press
80kg × 8

Let's go.
```

- **Visible information:** remaining rest (**Hero**); `Next:` + new exercise name
  + its first set load × reps; encouragement (`Let's go.`). No set-progress line —
  this screen is about the next exercise, not the last.
- **Typography:** Hero = countdown → Body = `Next:` exercise name + load×reps →
  Encouragement (accent).
- **Actions:** whole screen = **Ready** (begin the new exercise now). Pause
  affordance.
- **Haptics:** **Rest Complete** on elapse (wrist-down capable), same go-signal as
  Inter-Set Rest. (The *boundary* was already marked by the Exercise Complete
  haptic; rest end is the same "go".)
- **Transitions:** on elapse or Ready → Active Set for the new exercise.
- **Wrist-down / wrist-up:** Always-On countdown live; wrist-up reveals the new
  exercise block + encouragement + Ready.
- **Failure states:** identical to Inter-Set Rest — countdown safe and live, Ready
  disabled while disconnected, *Continue on iPhone* on a prolonged drop.

### 2.6a Exercise Busy (one tap, no menus)

Matches the phone exactly: the current exercise is swapped with the **next
pending exercise** (its whole set-run moves one position later); structure, loads,
and targets are unchanged. There is no replacement menu and no exercise picker.

```
Before:  1. Bench Press   2. Incline Press   3. Fly
After :  1. Incline Press 2. Bench Press     3. Fly
```

- **Trigger:** the **Exercise Busy** button on the Active Set screen (available
  only at the start of an exercise that has a later exercise to defer to).
- **Behavior:** one tap → the phone reorders → the watch **immediately enters the
  Active Set screen for the newly promoted exercise** (rendered from the fresh
  mirror). The Active Set screen is unchanged and still offers **Complete Set** and
  **Couldn't Complete** (and `Exercise Busy` again if the new exercise also has a
  later one).
- **No additional decision points.** One tap. Continue training.
- **Haptics:** a light **action ack** to confirm the swap registered (an action
  acknowledgment, not a progress event).
- **Failure states:** if the phone cannot be reached, the swap is not applied
  locally (the watch owns no plan); the button shows disabled and the screen
  indicates *Reconnecting*. The athlete can defer on the phone or retry on
  reconnect. The watch never reorders on its own authority.

### 2.6b Couldn't Complete → Rep-adjustment screen (ratified)

The watch captures **actual performance exactly the way the phone does**. When the
athlete can't hit the prescribed reps, they report what they did — no special
failure model, no watch-only semantics. The watch is simply reporting actual reps.

```
Actual reps

   6

Target 8

[ Confirm ]
  Cancel
```

- **Trigger:** the **Couldn't Complete** action on Active Set (always present
  alongside Complete Set). It opens this screen (a local UI step, not a wire event).
- **Default value:** `target_reps` (here, 8). The athlete adjusts with the **Digital
  Crown** and confirms.
- **Visible information:** the title `Actual reps`; the adjustable value (**Hero**,
  Crown-driven); `Target N` as a reference. Confirm (primary), Cancel (back).
- **On Confirm:** the watch sends a normal **set completion carrying the actual
  reps** (weight stays the recommended target — the watch reports reps only). The
  **phone processes it exactly as if the athlete entered those reps on the phone**
  (the source of truth) — it persists `exercise · set_number · target_reps ·
  actual_reps` and runs its own machine transition (→ Inter-Set Rest / Transition /
  next / Workout Complete). This is the **actual completed set result**, not a
  research-only event.
- **Haptics:** Crown detents while adjusting (native); **Set Complete** tick on
  Confirm — a confirmed set is a confirmed set.
- **Cancel:** returns to Active Set with nothing logged.
- **Failure states:** if Confirm cannot reach the phone, nothing is recorded and the
  watch shows *Reconnecting*; the set is never double-recorded on reconnect.

> This closes the last gap: **Complete Set** (= target reps) and **Couldn't
> Complete → adjust** (= any actual reps) together let the watch report **every
> real workout outcome without exception**. Weight editing remains phone-only.

### 2.7 Paused

The coach waits, without nagging.

```
Paused

Bench Press · Set 2 of 4

[ Resume ]
   Finish
```

- **Visible information:** `Paused` (**Hero**); the frozen current context
  (exercise + set), dimmed; **Resume** (primary); **Finish** (secondary,
  separated, lower-emphasis).
- **Typography:** Hero = `Paused` → Body = frozen context (dimmed) → Resume label
  → Finish (distinct, smaller). The timer is **frozen** — no countdown is shown.
- **Actions:** whole screen = **Resume** (common, one tap). **Finish** is a
  separate, smaller bottom target that opens the Finish Confirmation (below) —
  it can never be hit by accident, and it is the single, deliberate exit.
- **Haptics:** **Settle** on entering Pause; **Affirm** on Resume.
- **Transitions:** entered via the Pause affordance from Active Set / either Rest.
  **Resume** returns to the *exact* prior state (a paused rest resumes its clock,
  restored by the phone). **Finish** → Finish Confirmation.
- **Wrist-down / wrist-up:** Always-On shows `Paused` dimmed, no timer (nothing is
  counting). Wrist-up reveals Resume / Finish.
- **Failure states:** Pause/Resume are requests to the phone. If unreachable, the
  watch cannot pause/resume it and shows *Reconnecting*; the phone is unaffected
  and can be controlled directly. The watch never fakes a pause it cannot enforce.

#### Finish Confirmation (explicit, two-step — finishing is destructive)

Ambiguous confirmation actions are not allowed. The prompt names the consequence;
the answers are unambiguous.

```
Finish Workout?

  No        Yes
```

- **Visible information:** `Finish Workout?` (**Hero/Title**); two clear buttons,
  `No` and `Yes`. (This replaces any prior `Continue` / `Finish` wording.)
- **Actions:** **Yes** → ends the workout (sends the finish intent) → Workout
  Complete. **No** → returns to Paused. No other paths.
- **Haptics:** none on the prompt itself; the **Workout Complete** signature fires
  only after `Yes` is confirmed and the phone saves.
- **Failure states:** if `Yes` cannot reach the phone, the workout is **not**
  ended and the watch shows *Reconnecting*; it never shows Workout Complete it
  cannot confirm. Because completed sets are already saved on the phone, finishing
  is non-destructive to logged work — but it still requires the explicit `Yes`.

### 2.8 Workout Complete

The Hush identity close — quiet, unmistakable.

```
Well Done.
```

- **Visible information:** `Well Done.` (**Hero**, verbatim, including the period).
  Optionally a single Caption (`Open Hush on iPhone.`) only when the session left
  something on the phone (a Portrait unlock, a standing receipt). No stats, no
  rings.
- **Typography:** Hero = `Well Done.` → optional Caption.
- **Haptics:** the **Workout Complete signature** (§3) — a dedicated pattern,
  distinct from set / rest / exercise / notification haptics. The athlete
  recognizes that the workout is fully complete **without looking**. This haptic is
  part of the completion experience, not an implementation detail.
- **Transitions:** arrives from the final set or from Finish Confirmation `Yes`.
  After a few seconds (or one tap to dismiss) the activity ends and the watch
  returns to its face. Nothing to navigate to.
- **Wrist-down / wrist-up:** the signature haptic fires regardless of wrist
  position; wrist-up shows `Well Done.`; it auto-dismisses either way.
- **Failure states:** shown **only when the phone confirms the save**. Until then,
  a calm `Saving…`; if the phone is unreachable, *Reconnecting* — never a premature
  or false completion.

### 2.9 Connection Lost (the trust state)

The most important state. The watch degrades to an honest viewer; the phone runs
the entire workout alone.

```
Reconnecting
( last-known state, dimmed behind )
Continue on iPhone
```

- **Visible information:** `Reconnecting` (Body weight, accent) over the dimmed
  last-known screen so you still see where you were. A running rest countdown (if
  any) keeps ticking (derived, safe). A gentle `Continue on iPhone` hint. No
  alert, no modal, no red.
- **Typography:** status over a dimmed prior hierarchy; nothing promoted.
- **Haptics:** a single **Connection Lost** tap on entering — soft, low, **once**,
  never repeated or escalating. **Affirm** on reconnect.
- **Transitions:** entered when reachability is lost or no fresh state arrives
  within a short grace window. Exits automatically on reconnect to the **current**
  live state (newest-state-wins — no stale frame). If the workout ended on the
  phone during the drop, reconnect lands on Workout Complete.
- **Wrist-down / wrist-up:** Always-On shows the dimmed last-known frame with a
  small reconnecting glyph; a derived rest timer keeps running. No new alarm on
  raise.
- **Interaction:** all phone-dependent actions are visibly disabled (~30% white).
  The watch **never blocks training**; the phone is fully functional on its own.
- **Failure within failure:** on a prolonged drop, the watch stops presenting a
  possibly-stale Active Set and settles into `Continue on iPhone` with the app
  idling, so it can never mislead. It logs nothing, queues nothing, invents
  nothing.

## 3. Haptic system (explicit mappings — no two major events feel alike)

Hush never uses a buzzy notification haptic. Each pattern has one job, and the
five **major** events are distinguishable by rhythm and intensity alone.

| Event | Pattern | Character | Fires wrist-down |
|---|---|---|---|
| **Set Complete** | 1 light tap | brief, minimal (the most frequent → quietest) | yes |
| **Rest Complete** | 2 taps, ascending, soft | a gentle "go" | **yes** |
| **Exercise Complete** | 3 even taps, gentle-firm | a closed phase / momentum | yes |
| **Workout Complete** *(signature)* | 2 soft taps → brief pause → 1 sustained warm tap | the only pattern with a pause + a sustained beat; unmistakable | yes |
| **Connection Lost** | 1 low, longer, descending tap | soft, non-alarming, once only | yes |

Supporting haptics (lower-frequency, user-initiated contexts, no confusion with
the majors):

| Event | Pattern | Notes |
|---|---|---|
| **Receipt** | 2 warm, firm, evenly-spaced taps | distinct from Rest Complete's *soft ascending* pair; only when Hush was right |
| **Settle** (pause) | 1 soft, longer tap | the workout stilled |
| **Affirm** (resume / reconnect) | 1 gentle tap | "back" |
| **Action ack** (Ready early, Exercise Busy) | 1 light tap | confirms a sent intent |

Design rule: progress is communicated through haptics **as well as** visuals. A
trained athlete can run a full session by feel — set, rest-end, exercise boundary,
and the final close are each recognizable without a glance.

## 4. State flow

```
                 Complete Set (= target reps) ──────────────┐
   Active Set ──┤                                            ├─► set completed
      │  │       └─ Couldn't Complete ─► Rep Adjust ─Confirm─┘    (rest >5s) ─► Inter-Set Rest ─► Active Set
      │  │                                  (Crown)                                (same exercise)     ▲
      │  │ set completed (rest ≤5s) ─────────────────────────────────────────────────────────────────┤
      │  │
      │  │ Complete Set (last set of exercise)
      │  ▼
      │  Exercise Complete ──► Transition Rest ──(Ready / elapse)──► Active Set (new exercise)
      │       (brief, haptic)     (new exercise)
      │
      │ Exercise Busy ──► (phone reorders) ──► Active Set (promoted exercise)
      │
      │ Pause                                   Complete Set (last set of session)
      ▼                                                    │
   Paused ──Resume──► (exact prior state)                  │
      │                                                    │
      │ Finish ──► Finish Workout?  ──Yes──────────────────┤
      │                  └──No──► Paused                    ▼
      └──────────────────────────────────────────►  Well Done.  ──► watch face

   Any state ──reachability lost──► Reconnecting ──reconnect──► current live state
```

## 5. Implementation interface (for future watch development)

This experience requires the following from the canonical mirror + protocol
(`src/platform/sessionMirror.ts`, `src/platform/watch/protocol.ts`). These are
the **only** additions beyond what already exists:

All non-native layers below are **implemented + tested** (209/209) as of
2026-06-16. Only the SwiftUI/WatchConnectivity native target remains.

- **Mirror — present:** `phase` (active_set / rest_inter / rest_transition /
  paused / complete), `setLabel` (`Set 3 of 4`), `targetWeight`/`targetReps`,
  `restEndsAt` (drift-proof countdown), `nextExerciseName` +
  `nextTargetWeight`/`nextTargetReps` (Transition Rest), **`completedExerciseName`**
  (Exercise Complete), **`canMarkBusy`** (Exercise Busy availability).
  `globalIndex`/`totalSets` remain in the mirror as the **authority/identity key**
  (optimistic concurrency on intents) but are **no longer displayed** on any screen
  (final adjustment §1). — `src/platform/sessionMirror.ts`.
- **Watch intents — present:** `complete_set` (now carries optional **`actualReps`**),
  `end_rest` (Ready), `pause`, `resume`, `finish_early`, `exercise_busy` (→ phone
  `markEquipmentOccupied`). Validation (freshness, dedupe, version, phase/index,
  `unavailable`) + serialization in `src/platform/watch/protocol.ts`. **Couldn't
  Complete is a local UI action** (opens the rep-adjustment screen); Confirm sends a
  `complete_set` with `actualReps`. The phone logs it via the normal completion path
  (`set_completed` telemetry + the persisted set log) — it is the actual set result,
  not a research-only event.
- **Presentation projection:** `src/platform/watch/watchPresentation.ts` —
  `projectWatchScreen(mirror, connection, localUi)` → the exact screen for every
  state (incl. `rep_adjust`), with actions + entry haptic. No `sessionProgress`
  field (removed §1). The native layer renders this; it computes nothing itself.
- **Haptic taxonomy:** `src/platform/watch/watchHaptics.ts` — the five distinct
  majors + supporting patterns + event→pattern mapping. A confirmed adjusted set is
  a normal **Set Complete** (`set_logged`).
- **Telemetry:** `src/platform/watch/watchTelemetry.ts` + `WATCH_EVENTS` — screen
  presented, haptic fired, finish prompted/resolved, exercise deferred, plus the
  lifecycle/intent events from `WatchSession` (`complete_set` carries `repsAdjusted`).
  All durable + append-only.
- **Client copy (i18n, founder-locked):** `watch.*` keys in `en.json` (incl.
  `Couldn't Complete`, `Actual reps`, `Target {{reps}}`, `Confirm`).

Everything else (offline rules, authority handshake, no-local-state) is unchanged
from `NATIVE_SURFACES.md` §4. The ONLY remaining work is native (see that file).

## 6. Constraints compliance

| Constraint | How this spec honors it |
|---|---|
| Phone is the source of truth | Every screen renders the phone's mirror; all actions are intents the phone validates and confirms. |
| Watch owns no workout state | The watch holds only the latest mirror for rendering + transient UI (a confirm dialog, an interstitial). It computes nothing authoritative; even the rest countdown is derived from a phone-supplied absolute end. |
| No local database | Nothing is persisted on the watch; nothing is queued. |
| No model execution | Targets, rest, ordering, receipts all originate on the phone/model. |
| One-tap common actions | Complete Set, Couldn't Complete, Ready, Resume, Exercise Busy, and the Finish answers are each a single tap. |
| No navigation tree | No tabs/back/scroll. The workout advances itself; Finish is the one deliberate, confirmed exit. |
| No scroll | Every screen fits one watch screen — confirmed per screen in §7. |

## 7. No-scroll compliance (confirmed)

Every approved screen fits one watch screen with **no scrolling** on the smallest
supported watch. Pause is a corner glyph (not counted as a row); secondary actions
are compact single-line text actions. Content budget per screen:

| Screen | Lines / elements | Fits one screen |
|---|---|---|
| **Active Set** | exercise name · `load × reps` (Hero) · `Set 3 of 4` · `Complete Set` (button) · `Couldn't Complete` (text) · [first-set only] `Exercise Busy` (text) · Pause glyph | ✅ (max 6 elements; common case 5) |
| **Inter-Set Rest** | countdown (Hero) · `Next:` + `load × reps` · encouragement · `Set 3 of 4` · Ready (full-screen) · Pause glyph | ✅ |
| **Transition Rest** | countdown (Hero) · `Next:` + exercise + `load × reps` · encouragement · Ready (full-screen) · Pause glyph | ✅ |
| **Exercise Complete** | `<Exercise> Complete` (Hero) · `Next:` + exercise | ✅ (no actions) |
| **Rep Adjustment** (Couldn't Complete) | `Actual reps` · value (Hero, Crown) · `Target N` · `Confirm` (button) · `Cancel` (text) | ✅ |
