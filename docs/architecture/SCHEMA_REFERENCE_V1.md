## 1. Zones (the schema's two-plus-infra structure)

The schema has two **logical zones** plus bookkeeping/infra (§5 of the as-built doc):

- **Immutable history (append-only facts)** — the reconstructable audit chain. Written once, never
  mutated (lifecycle *status* on `workout_session`/`exercise_block`/`set_record` is the one
  partial-by-design exception — see the invariant matrix in the as-built doc, ATD-9).
- **Mutable projection (current state)** — the derived "where the athlete is now"; rewritten by the sole
  `StateRepository` writer (ES-007).
- **Runtime / surfacing projections** — per-session and stagnation-surfacing memory (DX-11 / DX-09).
- **Web-shell infra** (migrations 010/011) — auth, idempotency, erasure tombstone; outside the model zones.
- **Bookkeeping** — `schema_version`.

| Zone | Tables |
|---|---|
| Immutable history | `workout_session`, `exercise_block`, `set_record`, `observation`, `evidence`, `recommendation`, `state_update_log`, `shadow_recommendation` |
| Mutable projection | `athlete`, `athlete_state`, `capability_state`, `strategy_state`, `preference_state` |
| Runtime / surfacing | `session_progress`, `stagnation_marker` |
| Web-shell infra | `auth_token`, `idempotency_key`, `erasure_record` |
| Bookkeeping | `schema_version` |

## 2. ER overview (foreign-key topology)

`athlete` is the root identity; almost everything hangs off it. The history chain narrows
session → block → set → observation → evidence → state_update_log.

```
athlete (id) ──┬──< athlete_state            (1:1 projection)
               ├──< capability_state          (1:N, PK athlete_id+capability)
               ├──< strategy_state            (1:1 projection)
               ├──< preference_state           (1:N, PK athlete_id+exercise_family)
               ├──< auth_token                 (1:N, PK token_hash; revocable)
               ├──< workout_session ──< exercise_block ──< set_record
               │           │                   │              │
               │           │                   │              └──< observation (set_id)
               │           └── session_progress (PK session+capability)
               ├──< recommendation ──(exercise_block_id, nullable)
               ├──< observation ──< evidence ──< state_update_log
               ├──< shadow_recommendation ──(recommendation_id, nullable)
               └──  erasure_record / stagnation_marker / idempotency_key  (keyed by athlete_id; no FK*)

  *stagnation_marker, idempotency_key, erasure_record are athlete-keyed but NOT FK-constrained to
   athlete(id): they are infra/surfacing tables that must survive/lead independently of athlete-row
   lifecycle (e.g. erasure_record is a tombstone; idempotency_key gates replays before any row exists).
```

FK constraints present (from `PRAGMA foreign_key_list`): `athlete_state`, `auth_token`,
`capability_state`, `evidence` (→observation, →athlete), `exercise_block` (→workout_session),
`observation` (→set_record, →exercise_block, →workout_session, →athlete), `preference_state`,
`recommendation` (→exercise_block nullable, →athlete), `session_progress` (→workout_session),
`set_record` (→exercise_block), `shadow_recommendation` (→recommendation nullable, →athlete),
`state_update_log` (→evidence nullable, →athlete), `strategy_state`, `workout_session` (→athlete).

## 3. Tables & columns (v11)

PK = primary key (composite where two columns are marked). Version-stamp columns
(`model_version`/`capability_model_version`) on history rows are the BB-4 traceability anchor; bump policy
in `VERSIONING_POLICY_V1.md`.

### Mutable projection
- **athlete** — `id` PK, `sex`, `age`, `experience`, `created_at`, `bodyweight_kg` (DX-07, nullable). The
  identity row; precise identifiers (`age`, `bodyweight_kg`) are nulled on erasure (OD-2).
- **athlete_state** — `athlete_id` PK→athlete, `workout_count`, `fatigue_systemic`, `last_workout_at_week`,
  `updated_at`.
- **capability_state** — (`athlete_id`,`capability`) PK→athlete. The per-capability core+variance+decision
  +fatigue "god-row" (ATD-7): `score`, `confidence`, `sum_w`, `last_trained_at_week`, `fatigue`,
  `var_w`/`var_ws`/`var_ws2`, `last_recommended_weight`, `last_decision`, `consecutive_positive/negative`,
  `last_decision_week`, `updated_at`.
- **strategy_state** — `athlete_id` PK→athlete, `weekly_frequency`, `weekly_volume`, `primary_focus`,
  `secondary_focus`, `updated_at`.
- **preference_state** — (`athlete_id`,`exercise_family`) PK→athlete, `preference_score` (DX-10 sticky;
  default 50), `updated_at`.

### Immutable history
- **workout_session** — `id` PK, `athlete_id`→athlete, (+ status/timing columns); the session root.
- **exercise_block** — `id` PK, `workout_session_id`→workout_session, `capability`, `exercise`,
  `difficulty_factor`, `position`, `recommended_weight`, `target_reps`, `target_sets`, `status`,
  `selection_reason`.
- **set_record** — `id` PK, `exercise_block_id`→exercise_block, `set_number`, `recommended_weight`,
  `target_reps`, `actual_weight` (nullable until logged, M1 input), `actual_reps`, `status`, `completed_at`.
- **observation** — `id` PK; FKs to `set_record`, `exercise_block`, `workout_session`, `athlete`;
  `capability`, `exercise`, `difficulty_factor`, `actual_weight`, `actual_reps`,
  `predicted_reps_to_failure`, `prediction_error`, `week`, `override_category` (A9), `override_target`,
  `created_at`.
- **evidence** — `id` PK, `observation_id`→observation, `athlete_id`→athlete, `capability`, `s_obs`,
  `quality`, `weight`, `source_week`, `model_version`, `capability_model_version`, `created_at`.
- **recommendation** — `id` PK, `exercise_block_id`→exercise_block (nullable), `athlete_id`→athlete; the
  full advisory record incl. `decision_type`, `target_load`, `replaced_from_exercise`/`replace_reason`
  (DX-10), `est_fatigue_*`, `prediction_confidence`, `decision_reason`, `model_version`,
  `capability_model_version`, `created_at`.
- **state_update_log** — `id` PK, `athlete_id`→athlete, `evidence_id`→evidence (nullable); the before/after
  capability transition: `prev_*`/`new_*` (score/confidence/sum_w), `reason`, `agreement`, `sigma2_recent`,
  `est_fatigue_capability`, `decision_type`, `model_version`, `created_at`.
- **shadow_recommendation** — `id` PK, `recommendation_id`→recommendation (nullable), `athlete_id`→athlete;
  the A8 shadow-baseline paired record: `shadow_weight`, `shadow_predicted_rtf`, `model_predicted_rtf`,
  `actual_reps`, `week`, `created_at`.

### Runtime / surfacing projection
- **session_progress** — (`workout_session_id`,`capability`) PK→workout_session (DX-11 event-driven
  runtime): `entry_score`, `s_obs`, `decision_type`, `recommended_weight`, `have_primary`, `updated_at`.
- **stagnation_marker** — (`athlete_id`,`capability`) PK (DX-09 M5 read-only surfacing memory):
  `last_surfaced_week`, `last_surfaced_state`, `updated_at`. No FK (surfacing memory, independent lifecycle).

### Web-shell infra (migrations 010/011)
- **auth_token** — `token_hash` PK (peppered SHA-256, BB-20), `athlete_id`→athlete, `created_at`,
  `revoked_at` (nullable; non-null ⇒ revoked → 401).
- **idempotency_key** — (`athlete_id`,`client_event_id`) PK (BB-1), `response_json`, `created_at`. No FK
  (gates a replay before/independent of athlete rows). Anti-double-apply + anti-replay.
- **erasure_record** — `athlete_id` PK (OD-2 tombstone), `erased_at`, `method` (= logical anonymization).

### Bookkeeping
- **schema_version** — `version` PK, `applied_at`. A fresh DB stamps the **full chain** (ATD-12); the
  migration runner stamps each applied step. Head = 11.

## 4. Notes for operators

- **Fresh-vs-migrated parity (ATD-8):** a fresh `SCHEMA_SQL` DB and a fully-migrated DB have identical
  table/column shape *and* `schema_version` contents — the drift guard + per-migration parity tests
  enforce this. `python -m app.migrate --db <path> --verify-only` asserts the deployed DB matches this
  reference (head + chain + integrity + FK + shape parity).
- **Erasure (OD-2)** removes `auth_token` + `idempotency_key` rows and nulls precise identifiers on
  `athlete` (exact `age`, `bodyweight_kg`) while keeping coarse cohort labels (`sex`, `experience`) the A7
  validation needs; the immutable history is left intact (anonymized by the identifier nulling), and an
  `erasure_record` tombstone is written.
- **Stale dev DBs:** the repo's `hush.db` is a v10 dev artifact (no `erasure_record`); it is **not** the
  reference — this document reflects the v11 head produced by `SCHEMA_SQL`.
